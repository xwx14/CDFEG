# 设计：前后处理配置上提（`_resItems` → `DomainData::PrePostConfig`）

> 日期：2026-07-25
> 范围：CDFEG 核心库（DLL）+ sample 示例集 + pyTool 代码生成器
> 不涉及：`GidPrePost2`（保持现状）；单元子程序 `uEle` 语义（不改任何 stress 的 OnNodes/OnGaussPoints 归属）
> 前序：[`2026-07-25-多processor统一后处理与resItem通用化-design.md`](./2026-07-25-多processor统一后处理与resItem通用化-design.md) —— **已实施**：`_resItems` 已由 `GidPrePost` 上移至 `Processor` 基类（每实例一份），`ResItem`/`ResLocation`/`ResType` 已通用化，`DomainData::post(it)` 统一入口与 vtkPost 多步 PVD 已就位。本设计是该改造的**下一步延续**。

## 1. 背景与目标

前序 spec 把结果项从 `GidPrePost` 私有提升到 `Processor` 基类（每实例一份），解决了"结果项定义耦合 GiD 专有类型"的问题。但配置仍挂在**处理器实例**上，带来三个遗留矛盾：

1. **关注点错层**：结果项定义本是"问题域"信息（要输出哪些场量），却存在处理器实现层；同一份配置需在每个 processor 上各注册一次（DEl2D 对 gid/vtk 各 `registerItems` 一遍）。
2. **节点/单元结果混桶**：`_resItems` 同容器混装 `OnNodes` 与 `OnGaussPoints`，post 内靠 `item._loc` 运行时分流，节点结果与单元结果的边界隐式。
3. **analysis 名硬编码**：`gidPrePost.cpp:478/501` 写死 `"Load Analysis"`，无法配置。

**目标**：

1. 新增 `PrePostConfig` 类承载前后处理配置，以**值成员**组合到 `DomainData`；
2. 结果项拆为 `_nodeResItems`（节点，取各场 `_nodeRes`）与 `_eleResItems`（单元，取各场 `_elemRes`）两桶；
3. 多 processor 共享 `DomainData` 上一份配置；
4. GiD analysis 名可配置（默认值 = 现硬编码值，行为不变）；
5. `ResItem` 接口（含 `_loc`）保持不变；示例输出数值零回归。

## 2. 设计决策（已确认）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 配置范围 | 广义：`_nodeResItems` + `_eleResItems` + `_analysisName` + `_bNeedTime`(预留) | 用户定位于"前后处理配置"类，预留扩展位 |
| `ResItem._loc` | **保留** | 接口稳定；容器分桶后 `_loc` 作 ResItem 自描述，分流改由容器决定 |
| 多 processor 共享 | DomainData 持单一份，所有 processor 遍历同一份 | 配置归问题域；DEl2D 双注册合并为一次 |
| 组合方式 | DomainData 值成员 `PrePostConfig _prePostConfig` | KISS，无指针管理，访问 `_femData->_prePostConfig.xxx` |
| 验证范围 | 仅配置重构，不改示例 stress 语义 | 单元结果路径（truss force/stress）已有示例在用，无需额外激活 |

## 3. 详细设计

### 3.1 新类 `PrePostConfig`（新文件 `FEMproject/CDFEG/PrePostConfig.h`）

纯数据配置类，仅头文件（无方法，不建空 `.cpp`）：

```cpp
#ifndef PRE_POST_CONFIG_H
#define PRE_POST_CONFIG_H
#include <string>
#include <vector>
#include "CDFEG.h"
#include "ResItem.h"
namespace CDFEG {
    class CDFEG_API PrePostConfig {
    public:
        // 节点结果项（OnNodes，post 取各物理场 _nodeRes）
        std::vector<ResItem> _nodeResItems;
        // 单元结果项（OnGaussPoints，post 取各物理场 _elemRes）
        std::vector<ResItem> _eleResItems;
        // GiD 结果 analysis 名（gidPrePost 写 Result 头用，默认沿用原硬编码值）
        std::string _analysisName = "Load Analysis";
        // 预留：processor 是否需要时间信息（当前未启用，从前序 Processor 基类迁入）
        bool _bNeedTime = false;
    };
}
#endif
```

### 3.2 `DomainData` 组合

`DomainData.h`：新增 `#include "PrePostConfig.h"`，public 成员区增：

```cpp
PrePostConfig _prePostConfig;
```

### 3.3 `Processor` 改造（变薄）

`Processor.h`：
- 移除 `std::vector<ResItem> _resItems;`（迁入 PrePostConfig 的两桶）
- 移除 `bool _bNeedTime = false;`（迁入 PrePostConfig）
- 移除不再需要的 `#include "ResItem.h"`（基类不再直接持有 ResItem）
- 保留 `_femData / _nPts / _nEles`

子类经 `_femData->_prePostConfig` 访问配置。`GidPrePost2` 继承到该变化但不消费结果项（前序 spec 明确不涉及），无影响。

### 3.4 `ResItem`：不动

`_loc` 字段、`ResLocation` 枚举、构造第三参、`resLocationToStr/strToResLocation` 全部保留。

### 3.5 `gidPrePost::post` / `vtkPost::post` 改造

分流由**容器**决定，不再读 `item._loc`：

```cpp
// gidPrePost.cpp::post（原 for (ResItem& item : _resItems) + if(_loc==OnGaussPoints) 分流）
// 节点分支
for (ResItem& item : _femData->_prePostConfig._nodeResItems) { /* 原 OnNodes 段（行 501+）*/ }
// 单元分支
for (ResItem& item : _femData->_prePostConfig._eleResItems)  { /* 原 OnGaussPoints 段（行 455-500）*/ }
// analysis 名
outFile << "Result \"" << item._name << "\" \"" << _femData->_prePostConfig._analysisName << "\"  ";
```

`vtkPost.cpp::post` 两个循环（行 114 节点 / 行 135 单元）同样把 `_resItems` 替换为对应容器。

### 3.6 示例迁移（按 `_loc` 分流注册）

写入目标由 `xxx._resItems` 改为 `data._prePostConfig._nodeResItems` 或 `._eleResItems`，**按项的 `_loc` 决定桶**：

| 示例 | 结果项 | `_loc` | 归属容器 |
| --- | --- | --- | --- |
| Hel2D | temperature / disp / stress | OnNodes | `_nodeResItems` |
| El2D | disp / stress | OnNodes | `_nodeResItems` |
| ElT3 | disp / stress | OnNodes | `_nodeResItems` |
| DEl2D | disp / velocity / acceleration / stress | OnNodes | `_nodeResItems` |
| truss1D | disp | OnNodes | `_nodeResItems` |
| truss1D | force / stress | OnGaussPoints | `_eleResItems` |
| truss2D | disp | OnNodes | `_nodeResItems` |
| truss2D | force / stress | OnGaussPoints | `_eleResItems` |

**DEl2D 行为变化**：`registerItems` lambda 从 `[](CDFEG::Processor& p){...}` 改为 `[&data](){...写 data._prePostConfig...}`，由调两次（gid/vtk 各一）改为调一次，两 processor 共享遍历。输出文件（`.post.res` / `.vtu` / `.pvd`）格式与数值不变。

迁移写法示例（truss2D）：

```cpp
CDFEG::ResItem disp("disp", CDFEG::ResType::Vector);
disp.addVal(0, "u"); disp.addVal(0, "v");
data._prePostConfig._nodeResItems.push_back(disp);

CDFEG::ResItem force("force", CDFEG::ResType::Scalar, CDFEG::ResLocation::OnGaussPoints);
force.addVal(0, "T");
data._prePostConfig._eleResItems.push_back(force);
```

### 3.7 pyTool 同步

- `template/mainGid.cpp.j2`：`gidPrePost._resItems.push_back(resItemN)` → 按 `item.location` 分流：
  - `OnNodes` → `data._prePostConfig._nodeResItems.push_back(...)`
  - `OnGaussPoints` → `data._prePostConfig._eleResItems.push_back(...)`
  - 构造语句 `ResItem name(type[, ResLocation::OnGaussPoints])` 不变。
- `DataProject.py::addOutputItem`：docstring 同步（`location` 决定生成代码写入哪个容器）。

### 3.8 CMake 与文档

- `FEMproject/CDFEG/CMakeLists.txt`：`PrePostConfig.h` 列入源列表（项目约定：所有 `.h` 入 CMakeLists）。
- `FEMproject/CDFEG/代码解释.md`：vtkPost 段 "`_resItems`" → "`_nodeResItems`/`_eleResItems`（经 `_prePostConfig`）"。
- 核心库 `CLAUDE.md`：若有 `_resItems` 提及同步。

## 5. 验证方法

1. **全量 clean 重建**（mingw64，`--clean-first`）：核心库 DLL + 全部示例编译通过，grep 确认无残留 `_resItems`/`Processor::_bNeedTime`。
2. **e2e 回归全绿**：`python test/run_tests.py`，原有 case（`del2d1`/`hel2d1`/`el2d1`/`elt3_*`/`truss*`/`el2d_bf1`/`el2_mfel*`）位移/应力/内力 `max|Δ|` 不回归。重点关注 truss 的 `force`/`stress`（OnGaussPoints → `_eleResItems`）仍正常输出。
3. **DEl2D 多 processor 核查**：运行后 `del2d.post.res`（多步）+ `del2d_*.vtu` + `del2d.pvd` 与重构前一致；ParaView 打开 `.pvd` 仍可见 11 步动画。
4. **pyTool 生成器测试**：`python test/run_tests.py --suite generator` 通过，生成 main 与手写示例的注册写法一致。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `Processor::_resItems` 移除遗留旧符号 | 全量 `--clean-first` 重建；grep 确认无残留 `_resItems`/`_bNeedTime`（核心库 + 示例 + pyTool） |
| truss `force`/`stress` 误塞 `_nodeResItems` 致单元结果丢失 | 迁移严格按 `_loc` 分流（见 §3.6 表）；回归验证 truss 内力/应力仍输出 |
| DEl2D 共享后 gid/vtk 输出变化 | 两 processor 遍历同一份配置、各写各的格式，输出文件不变；e2e 对比 `.post.res` 与 `.pvd` 基线 |
| pyTool 生成物与手写不一致 | 重跑 generator 测试；`mainGid.cpp.j2` 按 location 分流两桶 |
| `_loc` 与容器不一致的隐性 bug | post 以容器分流为准，`_loc` 不参与逻辑；后续可加防御性断言（非本次范围） |

## 7. 行为变化小结（仅此 3 点，输出数值不变）

1. `Processor` 不再有 `_resItems` / `_bNeedTime` 成员（迁入 `DomainData::_prePostConfig`）。
2. DEl2D 的 gid + vtk 从"各持一份结果项"变为"共享 DomainData 一份"。
3. GiD analysis 名可配置（`_analysisName`，默认 `"Load Analysis"` = 原硬编码值）。

**迁移策略**：一次性全改（核心库 + 6 示例 + pyTool + 文档），无外部 API 兼容负担（示例与 pyTool 是唯一直接消费方）。
