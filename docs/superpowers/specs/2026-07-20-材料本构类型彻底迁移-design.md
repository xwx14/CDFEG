## 1. 背景与动机

P0 把材料参数 schema 上移到 `DomainData._mateConstitutive`、单元持 `_mateTypeName`，readMate 本构表优先。但 P0 **保留** `ElementBase._paramNames` 作 readMate 回退（旧示例零改动）。回退分支使材料段名约定（去 `mat_` 前缀）需在 readMate 存 / setEleMate 查两侧维护，且 `_paramNames` 与本构表存在双源风险。

P1 彻底删除 `_paramNames` + readMate 回退，改由 `DataProject.makeData` 自动建本构表——单元只声明自己的 `paramNames`（pyTool 数据模型输入），makeData 按规则（单物理场用单元名、多物理场用 gidName）自动建本构表 + 设 `mateTypeName`。消除双源，简化 readMate（只走本构表）。

## 2. 目标与非目标

### 目标

1. 删除 `ElementBase._paramNames`；readMate 删回退，只走本构表 `_mateConstitutive`。
2. `DataProject.makeData` 自动建本构表：单物理场本构名 = 单元 `name`；多物理场本构名 = `gidName`（同 gidName 保序合并去重）；自动设 `ele.mateTypeName`。
3. 所有 sample（含 truss makeData 入口）DomainData 构造注册 `_mateConstitutive`（保持一致）。
4. Hel2D `testHel2d.py` 恢复 `paramNames`+`gidName` 写法（删 P0 手动 `addMateType`/`mateTypeName`），与其他 test*.py 统一。
5. 测 `pyTool/test/truss1D` 框架生成（验证 pyTool 产出 `_mateTypeName`/`_mateConstitutive`、无 `_paramNames`）。
6. 全量回归 11 用例通过。

### 非目标

- 不改 sample 物理逻辑（run/uEle）。
- 不删 `DataEleSub.paramNames`（Python 数据模型，作 makeData 建表输入）。
- 不动 GUI、preParser、MakerGidFile（留后续）。

## 3. 设计决策（已确认）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 多物理场 paramNames 合并 | 保序合并去重 | Hel2D 无重复；未来同名参数自动去重，避免 readMate 命名冲突 |
| truss 本构注册 | 加（保持一致） | 所有 sample 形式统一，即使 makeData 入口不经 readMate |
| Hel2D testHel2d 写法 | 恢复 paramNames+gidName | makeData 自动建表，与其他 test*.py 统一 |
| 本构名规则 | 单物理场=单元 name；多物理场=gidName | 单物理场每单元一本构；多物理场共享 |

## 4. 核心库改动

### 4.1 `ElementBase.h` — 删除 `_paramNames`

### 4.2 `gidPrePost.cpp::readMate` — 删回退，只走本构表

替换为（去掉 else 回退分支）：
```cpp
int GidPrePost::readMate(const std::map<std::string, std::string>& params)
{
	std::string name = params.at("name");
	auto itType = _femData->_mateConstitutive.find(name);
	if (itType == _femData->_mateConstitutive.end()) return -1;
	const std::vector<std::string>& mateparams = itType->second;
	const std::string& line = _datReader.getCurrentLine();
	int i = 0;
	while (_datReader.readNextLine()) {
		if (line[0] == '*') { _datReader.preLine(); break; }
		std::vector<double> vals = TextReader::splitDoubles(line, " ,");
		int len1 = vals.size();
		if (len1 > (int)mateparams.size()) len1 = mateparams.size();
		std::map<std::string, double> paramMap;
		for (int j = 0; j < len1; ++j) paramMap[mateparams[j]] = vals[j];
		_femData->addMate(paramMap, name+"_" + std::to_string(++i));
	}
	return 0;
}
```

> readMate 不再遍历单元、不再依赖 `_paramNames`；材料段头 `name` 必须是 `_mateConstitutive` 的 key（本构类型名）。

## 5. pyTool 改动

### 5.1 `DataProject.makeData` — 自动建本构表

在 `field.makeData()` 循环后追加建表逻辑：
```python
def makeData(self):
    for field in self.fields:
        field.makeData()
    # 建立本构表：单物理场用单元 name，多物理场用 gidName（同 key 保序合并去重）
    self.mateTypes = []
    multiField = len(self.fields) > 1
    for field in self.fields:
        for ele in field.eleSubs:
            constitutiveName = ele.gidName if multiField else ele.name
            ele.mateTypeName = constitutiveName
            self._mergeOrAddMateType(constitutiveName, ele.paramNames, ele.paramValues)

def _mergeOrAddMateType(self, name, params, values):
    """注册或合并本构类型：同名保序合并去重，否则新增。"""
    for mt in self.mateTypes:
        if mt['name'] == name:
            seen = set(mt['params'])
            for i, p in enumerate(params):
                if p not in seen:
                    seen.add(p)
                    mt['params'].append(p)
                    mt['defaults'].append(values[i] if i < len(values) else 0.0)
            return
    self.addMateType(name, params, values)
```

要点：
- 单物理场（`fields.size<=1`）：本构名 = 单元 `name`，每单元一本构（El2D 三单元 → 三本构）。
- 多物理场：本构名 = `gidName`，同 gidName 合并（Hel2D 两单元 gidName=HelQ4g → 一本构 HelQ4g，参数保序合并去重）。
- 自动设 `ele.mateTypeName`，用户无需手设。

### 5.2 移除 `MakerCpp._applyMateTypeCompat`

P0 的 `_applyMateTypeCompat`（未声明 mateTypeName 的单元默认注册）被 makeData 取代。删除该方法 + `_build_render_data` 末尾的调用。makeData 在 `MakerCpp.makeProject` 调 `project.toDict()` 前已执行（`_build_render_data` 调 `field.makeData`，但 `project.makeData` 需显式调）。

> **调用时机**：`MakerCpp.makeProject` 在 `_build_render_data(project)` 后、`_makeDomainData`（用 `project.toDict()`）前，追加 `project.makeData()`。确保 `mateTypes`/`mateTypeName` 在 toDict 前就绪。

### 5.3 `DataEleSub.paramNames` 保留

作 makeData 建表输入，不删。`toDict`/`fromDict` 已含（P0）。

### 5.4 模板无需改

`elesub.cpp.j2`（输出 `_mateTypeName`）、`domaindata.cpp.j2`（输出 `_mateConstitutive`）P0 已改，本 spec 沿用。
