## 1. 背景与动机

### 1.1 现状机制

`gidPrePost.cpp::readMate`（行 176-206）当前按如下方式读取材料段：

1. 材料段头 `* name=<X>, type=mat`，取 `X`；
2. 遍历所有场所有单元，匹配 `"mat_" + 单元._name == X`，命中单元 `curEle`；
3. 用 `curEle->_paramNames` 为材料数值逐行命名；
4. `addMate(paramMap, X + "_" + i)` 存入 `DomainData._mateParams/_mateNames`。

即：**材料 schema（参数名列表）挂在单元 `ElementBase._paramNames` 上**，材料段名绑定到**单元 `_name`**。

### 1.2 Hel2D 暴露的矛盾

`testHel2d.py` 中热场单元 `HeatQ4g`（参数 `ek/ec/q`）与位移场单元 `DelQ4g`（参数 `pe/pv/fu/fv/rou/alpha/alfa`）共享同一种 GiD 单元 `HelQ4g`，需要一段统一材料 `mat_HelQ4g`（全量 10 参数）。

但按现状 `readMate`：

- 两个单元 `_name` 不同（`HeatQ4g`/`DelQ4g`），无法都匹配 `mat_HelQ4g`；
- 两个单元 `_paramNames` 不同（3 个/7 个），无法都正确命名全量 10 个值。

**当前 workaround**（`Hel2D/HeatQ4g.cpp`、`DelQ4g.cpp` 手填）：把两个单元 `_name` 都改成 `"HelQ4g"`、`_paramNames` 都改成全量 10 个。代价：

- 单元 `_name` 被污染（违反"`_name` 与 dat elem `name` 一致"约定）；
- 每个单元冗余持有全量参数 schema，新增参数需改所有单元；
- **pyTool 生成的框架无法直接用于耦合场，必须手改**。

### 1.3 GiD 层已部分解决

`MakerGidFile.py:73-96` 已按 `gidName` 合并各单元 `paramNames` 生成统一材料卡片（`提示词.md` 记录）。但核心库 `readMate` 仍按单元 `_name` 工作——**两层不一致**。本改造将统一到"本构类型"维度。

## 2. 目标与非目标

### 目标

1. 材料参数 schema 上移到 `DomainData`，单元仅持本构类型引用；
2. `readMate` 用材料段头本构类型名直接查表，脱离单元 `_name`；
3. pyTool 能直接生成可编译运行的 Hel2D 框架，无需手改 `_name`/`_paramNames`；
4. 现有单场示例（truss/El2D/ElT3/DEl2D）零改动兼容。

### 非目标

- 不改变材料**值**的绑定机制（`setEleMateByName`/`setEleMateByInternal`/`_eleMateIds` 维持现状）；
- 不改变材料数值的存储结构（`_mateParams`/`_mateNames` 维持 `vector<map>`+序号命名）；
- 不引入本构类型的继承/层级（仅扁平 `map<string, vector<string>>`）。

## 3. 设计决策（已确认）

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 本构表归属 | `DataProject` 全局表 + `DomainData._mateConstitutive` | 本构是跨场物理属性，单元/场共享 |
| 单元 `paramNames` 去留 | 删除 C++ 端 `_paramNames`；pyTool `DataEleSub.paramNames` 保留为兼容输入字段 | 与核心库对齐（单一数据源），旧脚本平滑过渡 |
| 材料段命名 key | 本构类型名（`* name=<本构类型名>, type=mat`） | `readMate` 直接查表，单元 `_name` 可恢复真实名 |
| 迁移策略 | 自动兼容：未声明 `mateTypeName` 时默认 = 单元名并用 `paramNames` 自动注册同名本构 | 单场示例零改动 |

### 4.3 `gidPrePost.cpp::readMate`

```cpp
int GidPrePost::readMate(const std::map<std::string, std::string>& params) {
    const std::string& name = params.at("name");                       // 本构类型名
    auto it = _femData->_mateConstitutive.find(name);
    if (it == _femData->_mateConstitutive.end()) return -1;
    const std::vector<std::string>& mateparams = it->second;
    const std::string& line = _datReader.getCurrentLine();
    int i = 0;
    while (_datReader.readNextLine()) {
        if (line[0] == '*') { _datReader.preLine(); break; }
        std::vector<double> vals = TextReader::splitDoubles(line, " ,");
        int len1 = vals.size();
        if (len1 > (int)mateparams.size()) len1 = mateparams.size();
        std::map<std::string, double> paramMap;
        for (int j = 0; j < len1; ++j) paramMap[mateparams[j]] = vals[j];
        _femData->addMate(paramMap, name + "_" + std::to_string(++i));
    }
    return 0;
}
```

要点：`readMate` 不再遍历单元、不再依赖 `ElementBase._name`；`_mateConstitutive` 须在 `pre()` 之前由 `DomainData` 派生类构造函数填充（见 §5.2）。

> 单元 `_mateTypeName` 在运行时仅作语义/校验用途（如 `pre()` 可校验其在本构表中存在），不参与材料读取。

## 5. pyTool 改造（本 spec 主体）

### 5.1 数据模型

#### `DataProject.py`

```python
def __init__(self, name="", dim=2):

    self.mateTypes = []          # [{name, params, defaults}]

def addMateType(self, name, params, defaults=None):
```

### 5.3 生成器

#### `MakerCpp.py` — 自动兼容（旧脚本零改动）

渲染前对每个单元补全 `mateTypeName`，并用 `paramNames` 自动注册同名本构类型：

```python
def _applyMateTypeCompat(self, project):
    existing = {mt['name'] for mt in project.mateTypes}
    for field in project.fields:
        for ele in field.eleSubs:
            if not ele.mateTypeName:
                ele.mateTypeName = ele.name                 # 默认 = 单元名
                if ele.paramNames and ele.name not in existing:
                    project.addMateType(ele.name, ele.paramNames, ele.paramValues)
                    existing.add(ele.name)
```

调用时机：`makeAll()` 渲染模板前。

#### `MakerGidFile.py` — 材料卡片改用 mateTypes 驱动（简化）

`_initFromProject` 当前把 `addElem`（单元几何卡片）与 `addMaterial`（材料卡片）放在同一 `gidName` 循环，并按 `gidName` 合并各单元 `paramNames`（`paramSeen`/`_1/_2` 序号逻辑，行 73-96）。改造后**两者拆分**：

- `addElem` 循环**保持**按 `gidName` 分组（单元几何定义不变，仅去掉合并 paramNames 的逻辑）；
- `addMaterial` 循环改为遍历 `project.mateTypes`（材料卡片由本构类型驱动）。

```python
# 单元几何卡片：仍按 gidName 分组（去掉 paramNames 合并）
eleGroups = {}
for field in pro.fields:
    ...添加场...
    for ele in field.eleSubs:
        eleGroups.setdefault(ele.gidName, {'ele': ele, 'fieldIndex': field.index})
for gidName, g in eleGroups.items():
    ele = g['ele']
    self.addElem(gidName, ele.nNodes, getEleTypeName(ele.type), ele.index, ele.bBC)

# 材料卡片：遍历本构类型；index 取首个引用场的 index（gidprb 模板当前未用 index，保守取值）
mtIndex = {}
for field in pro.fields:
    for ele in field.eleSubs:
        if ele.mateTypeName and ele.mateTypeName not in mtIndex:
            mtIndex[ele.mateTypeName] = field.index
for mt in pro.mateTypes:
    self.addMaterial(mt['name'], mt['params'], mt['defaults'], mtIndex.get(mt['name'], 1))
```

`template/gidprb.j2` 无需改动（仍消费 `materials[*].name/strParams/nParams/defaultParams`，未用 `index`）；材料卡片名天然 = 本构类型名。

## 8. 风险与对策

| 风险 | 对策 |
| --- | --- |
| `_mateConstitutive` 填充时机 | 放 `DomainData` 派生类构造函数（早于 `pre()`），安全 |
| 旧 dat 兼容 | 单场示例材料段名 = 单元名 = 本构名，天然兼容；多场耦合旧 dat 需统一为本构类型名 |
| sample 单元构造含 `_paramNames` 赋值 | 核心库删除该成员后，pyTool 生成单元改输出 `_mateTypeName`（模板）；手填单元（truss/El2D 等）需手改或经 pyTool 重生成，否则编译失败 |
| `DataEleSub.paramNames` 双源风险 | 生成器只读 `mateTypes`，C++ 不再输出 `_paramNames`；`paramNames` 仅作兼容入口，不进生成产物 |
| `test/truss1D/CDFEG/` 核心库快照含旧 `_paramNames` | 重生成时同步更新该快照，或调整 `MakerCpp` 的库复制逻辑跳过快照 |
| GUI 旧 `.cdfeg.json` | `fromDict` 全部用 `.get(..., 默认)`，旧存档自动补默认 `mateTypeName`/`mateTypes` |

## 9. 验证方法

1. **Hel2D（P0 主验收）**：重生成 → 编译 → 运行 → 对比位移/应力与 macs/hel 基准（`max|Δ|` 应达机器精度，参照 `macs到CDFEG升级方法.md` §10）。

3. **GiD 卡片**：检查 `.prb` 材料卡片名 = 本构类型名、参数列表与 `mateTypes` 一致。
