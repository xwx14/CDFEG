# GiD 示例单元量输出 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 4 个 GidPrePost 示例（DEl2D/El2D/ElT3/Hel2D）启用单元量输出（eleStress + eleVolume），同步 pyTool 配置与回归基线。

**Architecture:** 单元量管线已就绪（uEle→`_elemRes`→`gidPrePost::post`/`vtkPost::post` 写 OnGaussPoints/CellData）。本计划仅在各示例 main.cpp 注册 `_eleResItems`、在 test*.py 同步 `addOutputItem`、并 `--update` 刷新回归基线。核心库零改动。

**Tech Stack:** C++14 / CMake（mingw64 + Unix Makefiles）；Python 3 回归框架（`test/run_tests.py`）；pyTool Jinja2 生成器。

## Global Constraints

- **PATH**：`cmake`（`D:\greensoft\cmake-4.1.1`）与 `C:/dev/mingw64/bin` 须在 PATH（构建与 exe 运行 dll 加载）。
- **命名**：单元量 result_name = `eleStress`（Matrix）+ `eleVolume`（Scalar），驼峰；分量名须与各示例 `_eleResNames` 完全一致（见各 Task）。
- **核心库零改动**：不动 `FEMproject/CDFEG/` 任何文件；增量构建可靠（仅 main.cpp 改动 → main.o 重编 + 链接 exe）。异常时删 `test/build` 全量重建。
- **test*.py 仅配置同步**：本计划所有 `test*.py` 改动只追加 `addOutputItem` 作为生成器配置记录，**一律不得执行 `makeAll()` 重新生成**（DEl2D/Hel2D 的 main 是手填动力学/耦合逻辑，重生成会覆盖；El2D/ElT3 也以手动改 main 为准）。
- **基线刷新**：`python test/run_tests.py --update <case>`，逐用例、强制 `yes` 确认。`--update` 显示"新增结果段"为预期（即 eleStress/eleVolume），`max|Δ|` 应为 0。
- **提交**：commit 消息中文；按项目规范 git 操作需用户确认（执行时遵守）。
